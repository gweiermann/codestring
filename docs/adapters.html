Writing an adapter

An adapter teaches the core how to read one parser's output. It normalizes five things and implements no matching at all — if an adapter ever needs its own matcher, the abstraction has failed.

Experimental. codestring is an unmaintained experiment. The adapter contract below is what the six first-party adapters were written against and what the contract suite checks, but nothing here is frozen. Taking it over is very welcome.

The five required functions

import { defineAdapter } from "@codestring/core";

export const iniAdapter = defineAdapter<IniParsed, IniNode>({
  id: "ini",

  parse(source, options) { return parseIni(source); },  // your parser's own result
  root(parsed) { return parsed.root; },
  kind(node) { return node.type; },                     // a stable string per node type
  range(node) { return node.span; },                    // { start, end } in UTF-16 code units
  children(node) { return node.kids; },                 // source order, contained in the parent
});

defineAdapter infers your parser's types from the implementation, so every callback is checked against them and NodeRef.raw reaches users fully typed. If you would rather write the annotation yourself, LanguageAdapter<TParsed, TNode, TToken> is exported too.

The invariants

These are what the core relies on, and what it will reject you for breaking:

  • the root's range covers the whole parsed text, 0 to source.length
  • every range is integer offsets in UTF-16 code units — the same units String.prototype.slice uses
  • a node's text is exactly source.slice(node.start, node.end)
  • children are in source order and contained in their parent
  • kind is a non-empty string, stable for a node type across parses

Break one and you get an AdapterContractError naming the node and the offset, rather than a wrong match three layers up.

What each optional function buys

Everything below is optional, and each option buys exactly one behaviour. Add them when you want that behaviour, not as a matter of course.

FunctionWhat it enables
diagnostics(parsed)hasErrors(), and the parse-error policies. Report, never throw.
triviaClass(node)Whitespace-flexible matching. Without it, a pattern must spell out every space.
isErrorNode(node)Lets allow-outside-errors keep matches from the healthy parts of a broken file.
isVariadic(kind)Marks unbounded child lists, which is what makes a bare hole in one bind a run rather than a single node.
listSeparator(kind)What to insert between items when the list is too short to show its own separator.
isPatternWrapper(kind)A node the parser adds around a fragment, which a pattern should see through — an ExpressionStatement around foo().
compareText(node, text)Compare two leaves by what they say rather than how they were spelled — "a" and 'a' are the same string.
escape(value, ctx)Keep an interpolated plain value from breaking out of a literal. Source slices never go through it.
placeholder(i, ctx)Make a hole parseable in its context — see below.
isHoleKind(kind) / holeText(node, text)Which nodes may stand for a hole, and the text they are recognised by.

Placeholders: the one genuinely tricky part

A pattern with a hole has to be parsed before it can be matched. The core replaces each hole with a token — letters and digits, starting with a letter, chosen so the pattern's own text does not already contain it — and then finds the node whose text is that token. 

code`foo(${arg})`   →   parse("foo(cshole0)")   →   the Identifier at 4..11 is the hole

That works unmodified for most positions. It stops working where the grammar needs more than a bare name, and that is what placeholder is for: given what comes before and after, return the text to write there. 

// JavaScript: keep the token from fusing with an adjacent identifier
placeholder(_index, { before, after, fallback }) {
  const prefix = /[A-Za-z0-9_$]/u.test(before.slice(-1)) ? " " : "";
  const suffix = /[A-Za-z0-9_$]/u.test(after.slice(0, 1)) ? " " : "";
  return `${prefix}${fallback}${suffix}`;
}
// Vue: a closing tag has to repeat the opening name, or the compiler rejects it
placeholder(_index, { before, fallback }) {
  if (before.endsWith("</")) {
    const prefix = fallback.replace(/\d+$/u, "");
    const opened = new RegExp(`<(${prefix}\\d+)(?![\\s\\S]*</\\1>)`, "u").exec(before);
    return opened ? opened[1]! : fallback;
  }
  const insideTag = before.lastIndexOf("<") > before.lastIndexOf(">");
  return insideTag && !/\s$/u.test(before) ? ` ${fallback}` : fallback;
}

@codestring/adapter-utils ships the two helpers this keeps needing: isInsideDelimiter(before, open, close) and padPlaceholder(fallback, before, { needsSpace }).

Some positions cannot hold a hole at all. A tag name is one: <${x}> is an invalid-first-character-of-tag-name error in every HTML parser, whatever token you choose. That is a real limit of the approach, not something an adapter can paper over — the honest answer is to expose the tag as a kind (element:div) so a caller can ask about it without writing it in a pattern.

Trivia, separators and lists

Three classes exist, and each earns its place. whitespace and comment are what matching steps over. separator is punctuation that holds a list together — the , between arguments, the ; between CSS declarations.

Giving separators nodes of their own is what makes remove() correct. Without it, removing one argument of f(a, b) leaves f(, b); with it, the separator beside the removed run goes along. 

// the acorn and Babel adapters both do this, via a shared helper
import { separatorGaps } from "@codestring/adapter-utils";

const children = separatorGaps(converted, source, start, end, make);

isVariadic and listSeparator complete the picture. isVariadic("CallExpression") says the argument list is unbounded, so a bare hole there binds a run. listSeparator("CallExpression") === ", " is the fallback used when inserting into a list too short to show its own separator — a one-argument call has no comma to copy.

Reusing a tree someone else built

A parse is not always yours to make. ESLint already built an AST; a codemod may need @babel/traverse for the scope chain and cannot afford a second tree that drifts from the first. The pattern for both is the same — wrap the adapter so parse answers from the existing tree when asked for the same text: 

export function babelLanguage(file, source, options = {}) {
  const adapter = defineAdapter({
    ...babelAdapter,
    id: "babel",
    parse: (text, parseOptions) =>
      text === source ? fromBabel(file, source) : babelAdapter.parse(text, parseOptions),
  });
  return createLanguage(adapter, { parseOptions: options });
}

The fallback matters: a nested parse asks for a region, which the given tree cannot cover. With that in place, a node a pattern finds is the very node the caller's own traversal reaches — same object, not a copy at the same offsets.

Shipping standalone helpers

Keep the adapter dumb. But sometimes the normalized tree genuinely cannot express something every consumer needs, and then the honest answer is a plain function beside the adapter — never a method on it, and never special handling inside the core. 

// @codestring/vue — each takes a node and nothing else
export function tagOf(node: NodeRef<VueNode>): string | null {
  return isElement(node) ? node.kind.slice(node.kind.indexOf(":") + 1) : null;
}

export function attributesOf(node: NodeRef<VueNode>): NodeRef<VueNode>[] {
  return node.child("tag-open")?.child("attributes")?.children ?? [];
}

Two rules keep these from becoming a second API:

  • Standalone. A function of a node, importable on its own, working on a node from any construction of the language and on one from a nested parse.
  • Earned. Either it cannot be written without reaching past the normalized tree — nameOf needs the compiler's resolved directive name — or every consumer was about to write the same three hops anyway.

Prove it with the contract suite

import { runAdapterContractSuite } from "@codestring/testing";
import { iniAdapter } from "../src/index.js";

runAdapterContractSuite(iniAdapter, {
  valid: ["[section]\nkey = value\n", "; comment\n"],
  malformed: ["[unclosed\n", "= no key\n"],
  unicode: ["key = 🎉\n"],
  placeholderContexts: [{ before: "key = ", after: "\n" }],
});

Around ninety cases per adapter, checking ranges, ordering, containment, UTF-16 offsets, trivia classes, malformed input and placeholder round-tripping. Every first-party adapter runs it, and it is the fastest way to find out that your parser reports offsets in code points rather than code units.

A working order

  1. The five functions, nothing else

    Get language.parse(source).nodes() to print a tree that looks right. Run the contract suite with valid fixtures only.

  2. Trivia

    Classify whitespace and comments. Whitespace-flexible matching starts working, and patterns stop needing to spell out every space.

  3. Placeholders

    Add placeholderContexts fixtures for each position a hole should work in — inside a call, inside a tag, inside a string. Fix placeholder until they round-trip.

  4. Lists

    isVariadic so bare holes bind runs, separator nodes so remove() is correct, listSeparator so inserts land with the right punctuation.

  5. Spelling

    compareText if two spellings mean the same thing, escape if an interpolated value could break out of a literal.

  6. Malformed input

    diagnostics and isErrorNode. Add malformed fixtures — the suite insists you report rather than throw.
